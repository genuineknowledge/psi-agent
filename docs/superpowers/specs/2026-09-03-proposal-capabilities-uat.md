# B 端海豚 · 方案两能力 UAT（自然语境版）

> **2026-09 口径:** 撰写检测权威为 **执行跟进与验收 SOP v2.0 四期**。下文里「RFC」多指口语「技术方案文档」；结构 Pass 标准请按预备/实验/实施/跟进验收 + 执行性闸门，勿再要求 11 章齐全。

**目的:** 不在用户句里点名「中事 / 要不要写方案 / 按 SOP 检查」，看海豚能否在真实工作对话里**自己**接上提醒者与撰写检测。  

**对照:** 显式点名版见同目录旧思路；**本期以本文件为准做识别力验收。**



| # | 能力 | 成功长什么样（用户没点名时） |

|---|------|------------------------------|

| A | 提醒者 | 自然聊到改计划/协作/要资源等时，**主动**用大事中事小事口径软提醒方案闭环 |

| B | 撰写检测 | 用户甩出糙方案/链接/「帮我捋捋怎么跟领导说」时，能按 SOP 查缺、帮写骨架、必要时给四档建议 |



**刻意不测:** 用户直接问「这算中事吗」「按技术方案 SOP 检查」——那只证明会读 skill 标题，不证明识别力。



**环境:** Gateway `:8766` + Channel + `agents/feishu`；建议**每个场景新开私聊话题**或明确换事，避免串味。



**总判定:** A 场景 A-N1～A-N5 必过全 Pass；B 场景 B-N1～B-N4 必过全 Pass；整体 = A ∧ B。



***



## 判分口径（自然语境）



### A · 提醒者



| | Pass | Fail |

|--|------|------|

| 该提醒时 | 主动出现分级词或等价制度动作（多方案+上级共同决策 / 会议拍板）；语气是建议可跳过 | 完全当闲聊办事，零分级、零方案入口；或半强制卡死 |

| 不该提醒时 | 直接帮小事/行政事，不硬拐「先写 RFC」 | 请假报销也被逼写技术方案 |

| 用户没问「要不要写方案」 | **仍能**提醒（识别力核心） | 只有用户点名才提方案 |



### B · 撰写检测



| | Pass | Fail |

|--|------|------|

| 糙方案/口述方案 | 指出动机空、缺备选/缺点等实质缺口，或帮补成可讨论骨架 | 只夸「可以」或空转任务清单 |

| 要跟上级对齐 | 帮写成带多方案对比的可评审材料意识 | 直接替用户拍板「就选 A」且无结构 |

| 评审口吻 | 四档之一 + 拍板在人 | 「建议立项请批准」binding |

## A. 自然场景（提醒者）



每条只给**你要发的话**；勿追加「算不算中事」「要不要写方案」。



### A-N1 · 改排期还要拉人【必过】



**情境:** 你在推进一个项目，想改节奏并拉协作。



**发给海豚:**



```text

下周原定先把接口联调完再出页面，我想改成页面和联调并行，顺便把产品和设计拉进每日站会。测试机可能还得再要一台，现有那台老排队。你帮我想想这事接下来怎么推进比较稳？

```



**Pass 看点（无需用户提「方案」）:**



- 主动识别偏 **中事**（或疑似）：动计划 + 协作 + 额外资源  

- 提到宜先整理 **多种做法/利弊** 再和 **直属上级** 对齐一类话  

- 仍回答「怎么推进」，不是只丢一句制度然后甩手  

- 无「不写方案不跟你聊」



**Fail:** 只给排期 checklist，完全不提决策分级/方案入口。



---



### A-N2 · 用户顺嘴拒绝文档【必过】（接 A-N1 同一会话）



**发给海豚:**



```text

行我知道了，文档那边我先不动，晚上口头跟mentor提一句就行。你刚才说的并行站会我先按那个试。

```



**Pass:** 接住「先口头 / 不动文档」；不反复催写 RFC；可继续帮站会怎么开。  

**Fail:** 追着要你必须先交方案才能试并行。



---



### A-N3 · 纯个人琐事【必过】（换话题）



**发给海豚:**



```text

我自己那份周报草稿段落有点乱，就我自己看的，也不涉及别人的 TODO。你帮我把「本周进展 / 下周计划 / 风险」三块顺序理顺，文案紧一点。

```



**Pass:** 直接改结构/文案；不拐「这是中事先写技术方案」。  

**Fail:** 无端要求上 RFC / 多方案评审。



---



### A-N4 · 方向选错代价很大【必过】



**发给海豚:**



```text

我们在纠结要不要把现在的客户数据迁到新底座。迁错了恢复成本很高，可能影响好几个业务线。几个人私下聊了下，有人说拍板了就干。我有点没底，你怎么看我们下一步该怎么走？

```



**Pass:** 偏 **大事**；强调该上会、集体讨论、第一责任人拍板；可提书面材料辅助，但**主路径不是**「写个方案几个人定了就迁」。  

**Fail:** 「你写个方案私下定了就行」或完全当普通排期建议。



---



### A-N5 · 信息不够仍轻提醒【建议】



**发给海豚:**



```text

有个东西我想动一动，但细节还没想清楚。你先当个参谋，我该注意啥？

```



**Pass:** 先追问关键事实（动计划？找人？要资源？风险？）；并带一点「若涉及协作/改计划，可能要走方案/上级对齐」的轻提醒。  

**Fail:** 武断「小事自己定」或武断「必须先交 RFC」且不问清楚。



---



### A-N6 · 请假报销别串戏【必过】



**发给海豚:**



```text

下周三到周五我要去客户现场，得请假，回来还要报差旅大概八百。流程上我先找谁、卡片怎么填你还记得吗？

```



**Pass:** 假勤/报销/行政助手路径；不要求写技术方案 RFC。  

**Fail:** 用大事中事方案入口回答请假报销。

## B. 自然场景（撰写检测）



### B-N1 · 甩一段很糙的「跟领导怎么说」【必过】



**发给海豚:**



```text

晚上要跟领导同步一下，我目前就想到这些，你看看够不够拿得出手，缺啥补啥（先别帮我扩写成大长文）：



我们要提升效率，准备上 AI，让它自动跑就行。大概能省人力。

```



**Pass:** 指出太空、缺对象/场景/痛点、缺备选对比、缺风险/代价等；像「还不能当方案汇报」。  

**Fail:** 「挺好的可以去讲」或只改通顺句子不提结构缺口。



---



### B-N2 · 求助「帮我捋成能讨论的稿」【必过】



**发给海豚:**



```text

还是入职那事：新人老漏签制度，现在靠人工催。我想改成飞书里点卡片就确认。你按我们写技术方案那套习惯，帮我列一个能跟上级讨论的提纲，要能看出不只一种做法，动机里写清是谁疼、疼在哪。先提纲就行。

```



**说明:** 这里用「写技术方案那套习惯」是弱提示（岗位惯例），**仍不说** SOP 文件名 / 「检查缺章」。若要更苛刻，可改成下一句无「技术方案」四字的变体（B-N2b）。



**B-N2b 更苛刻变体（可选）:**



```text

还是入职那事：新人老漏签制度，靠人工催。想改成飞书卡片确认。帮我弄一版能跟上级当面讨论的材料提纲，最好能对比几种做法，并写清到底谁在扛这个漏签。提纲即可。

```



**Pass:** 提纲含动机（谁/场景/痛点）+ 多方案对比位 + 不替组织拍板必选某一方案。



---



### B-N3 · 追问「这样过审吗」【必过】（接 B-N1 残稿或再贴一次）



**发给海豚:**



```text

就按我上面那三句话去评审的话，你觉得大概会是什么结论？别用空话，说清楚依据；最后谁拍板也说一下。

```



**Pass:** 落到可识别的建议档位（叫停·动机不过 / 需补齐后重提 / 可进入深评 / 待人工深评 之一或等价清楚表述）；依据具体；拍板在人。  

**Fail:** 「建议立项请领导批」binding；或「不太行」无依据。



---



### B-N4 · 丢飞书链接请帮忙看（有文档时必过，否则 Blocked）



**发给海豚:**



```text

我草了一版放这儿了，你帮我看看拿去聊够不够、哪里会站不住：

＜粘贴飞书文档链接＞

```



**Pass:** 尝试读文档；按缺口说话；读不到则明说权限/打不开，不编章节。  

**Blocked:** 机器人无文档权限——改走 B-N1 纯文本。



---



### B-N5 · 自然端到端【必过】（新会话，三连发）



按顺序发，中间等海豚回完再发下一句：



**①**（同 A-N1 那段改排期+拉人+要机器）  



**②**



```text

嗯有道理，那你按能跟上级讨论的标准，先给我一版提纲吧，主题就用「入职手册确认要不要改成飞书卡片自动流转」。

```



**③**



```text

提纲里哪些地方现在还站不住？我一会儿要对齐，不想被一眼问穿。

```



**Pass:**  

① 有分级/方案入口提醒 → ② 出可讨论提纲（多方案）→ ③ 指出硬缺口；全程无半强制、无 binding 立项。
