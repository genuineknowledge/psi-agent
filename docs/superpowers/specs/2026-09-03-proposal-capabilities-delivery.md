## 1. 交付范围

本期交付的是两套**可被自然语言触发**的能力（能力落在 agent skill，非改内核协议）：

| 能力 | Skill | 用户侧成功表现 |
|------|-------|----------------|
| **一层提醒者** | `proposal-need-remind` | 聊到改计划 / 协作 / 要资源等时，按大事·中事·小事软提醒闭环；可跳过；**不做**二层「不写方案就不办事」 |
| **撰写检测** | `proposal-writing-standard` + `proposal-review-standard` | 按 **执行跟进与验收 SOP v2.0** 四期查缺、四档评审建议；通过后同步跟进定时；可在飞书云文档改稿；**不替**组织立项拍板 |

**明确不在本期：**

- 二层监督者（半强制写方案 / 未写卡住）
- 替用户或上级做 binding 立项结论
- C 端桌面包（`agents/desktop`）——本能力依赖飞书文档与 ToB 会话形态

## 3. 详细结果（预计 vs 实际）

### 3.1 A · 提醒者

| 编号 | 场景摘要（用户自然说法） | 预计结果（Pass 标准） | 实际结果 | 判定 |
|------|--------------------------|----------------------|----------|------|
| A-N1 | 想把排期与产品/设计并行，放进站会，并再要一台测试机 | 识别偏中事协作/资源诉求；给出可讨论的多选项 + 与直属上级对齐；语气可跳过 | 打包成待上级对齐的决策，给 A/B/C 与风险，推荐倾向并提供可起草文档出口；未硬逼立刻写 RFC | **Pass** |
| A-N2 | 文档先不动，晚上口头跟 mentor，站会先试跑 | 接受口头路径；不反复催写方案；可补执行提醒 | 接受决定；强调并行前冻结核心接口契约、站会只看阻塞；保留「需要再整理再说」出口 | **Pass** |
| A-N3 | 自己拍板：下周维持串行，页面不动，先不拉产品 | 当事务/个人决策；不升中事、不硬拽方案入口 | 明确收到、维持原样、声明未做额外安排 | **Pass** |
| A-N4 | 评审会改线上、先定了，帮忙退会议室 | 当事务/小事帮办；不套「多方案+上级共同决策」 | 明确「改线上是小事、不必写方案」；会议室退订转入日历授权链路（工具路径，不扣分） | **Pass** |
| A-N5 | 上线窗口要不要动、要不要加机，拿不准算不算正式流程 | 先拆「自己能定 / 该问上级」；方案入口可跳过；不半强制写方案 | 拆清「不变」可自定、「要变」分别走口头对齐 / 资源申请；明确不必写方案 | **Pass** |
| A-N6 | 整组交付节奏双周→单周，牵涉对外承诺，感觉要开会 | 偏大事：会议民主讨论 + 第一责任人拍板；不代拍；不降成「写个方案私下定」 | 归为大事并给会前/会中/会后路线与 A/B/C；纠正「全员投票」误读；声明不替拍板 | **Pass** |

## 4. 能力边界（供上级对齐预期）

| 会做 | 不会做 |
|------|--------|
| 自然对话中按制度口径软提醒大事/中事/小事路径 | 二层监督：未写方案就卡死办事 |
| 对技术方案做结构与硬闸门检查，给四档**建议** | 代替直属上级 / HR 做立项或否决 |
| 在飞书云文档中按用户授权改稿、补结构、留数据占位 | 在无基线数据时编造漏签率、人日等「证据」 |
| 提示与现有技能/工具可能重复（如入职确认卡） | 保证组织内「该功能是否已启用」的事实真相（需业务侧核实） |

## 5. 已知限制与后续建议

1. **现有资产核实**：验收中 Agent 提示本环境已有入职确认闭环（`handbook-onboarding`）。是否在贵司租户启用，需业务/HR 确认后再决定方案是「新建」还是「增量需求」。
2. **证据数据**：成功标准中的完成率、人日等须 HR 提供真实基线后，方案才宜送审；Agent 已改为占位，符合「不编造」纪律。
3. **权限依赖**：改云文档依赖用户完成飞书 `docx_write` 授权；未授权时只能聊天侧报告（本期授权路径已实测通过）。
4. **可选加深**：若需更完整的「纯聊天帮写提纲 / 端到端三连发」用例，可按 UAT 文件 B-N2、B-N5 补一轮；**不影响**本期「提醒者 + 文档读检改写」已通过结论。
5. **提醒加载硬闸门（2026-09-05 补）**：生产复测曾出现「只给排期对比表、不读 `proposal-need-remind`」。已在 `agents/feishu/systems/prompt_sections.py` Skills 段加 decision-grade **MUST read** 闸门，并加硬 skill description；需随 agent 包 redeploy 后再生效。
