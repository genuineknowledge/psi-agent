## 0. 一句话

撰写与审查解决的是「**写没写、写得合不合规、建议什么档位**」。  
后续环节要解决的是：「**按这份已认可的计划，事做到哪了、算不算做成**」——海豚的价值在**对照计划做进度镜像与缺口提示**，而不是再逼人写一篇 RFC。

---

## 1. 环节地图（已有 vs 要补）

```text
想法/诉求
  → [已有] 一层提醒：要不要走方案/会议路径
  → [已有] 撰写 + SOP 检查 + 四档评审建议
  → [要补] 跟进：计划落地过程中的进度与阻塞
  → [要补] 验收：对照计划判定「做成了没有 / 差什么」
  → [暂缓] 监督者二层：半强制写出方案
```

| 环节 | 用户问题 | 海豚价值（本稿） | 明确不是 |
|------|----------|------------------|----------|
| 提醒 | 这件事要不要正式想一想？ | 分级路径、可跳过 | 卡流程 |
| 撰写/审查 | 这篇写得规不规范？能不能进深评？ | 结构+硬闸门+档位建议 | 替上级立项 |
| **跟进** | 方案批了之后，做到哪了？卡在哪？ | 对照**计划步骤**汇总进度、催补证据、列缺口 | 替人改计划标准；无信号时装成已验收 |
| **验收** | 算不算按方案做成了？ | 按**同一套对照逻辑**给档位+缺什么 | 无反馈时硬宣判通过；与「写没写 RFC」混为一谈 |
| 监督二层 | 不写方案就不让办事？ | （暂缓） | 本期不排期 |

## 2. 跟进环节：海豚如何产生价值

### 2.1 价值主张

> **把「方案里的实施步骤」变成可持续对照的检查清单，在对话或定期节奏里回答：做到哪、证据在哪、下一步是什么。**

没有跟进时：方案通过评审后就「沉」进文档，进度只存在个人脑子或零散群聊里。  
有跟进时：执行者/mentor 问「XX 方案进展怎样」，海豚能**指向计划本身**作答，而不是临场编一套标准。

### 2.2 最小输入（跟进要吃什么）

访谈未拍板前，设计上先假定这三类输入（可被题2/题4/题6 修正）：

| 输入 | 作用 | 第一期可接受形态（草案） |
|------|------|--------------------------|
| **计划契约** | 对照物：步骤 + 可检验标准（+ 可选截止/负责人） | 已通过深评或作者自认的 RFC 中「实施步骤 / 成功标准」章节；或从方案拆出的待办列表 |
| **进度信号** | 「声称做到哪了」 | 对话自报；飞书任务勾选；文档/台账状态更新；卡片勾选（题2 定优先级） |
| **身份** | 谁的方案、谁在执行 | 会话/飞书 open_id；不发明第三套账号 |

**无进度信号时的产品行为（草案，对齐访谈题2 追问3）：**  
只输出「待补报 / 无法判定进度」，**禁止**输出「已按方案完成」类结论。

### 2.3 跟进时海豚具体做什么（能力列表）

| # | 能力 | 用户侧一句话 | 依赖 |
|---|------|--------------|------|
| F1 | **步骤投影** | 把方案里的实施步骤列成可勾选/可对照清单 | 能读到计划契约 |
| F2 | **进度对照** | 对每步：未开始 / 进行中 / 有证据待确认 / 已满足标准（用固定档位，禁止「基本完成」） | 进度信号；档位口径可与 `todo-completion-standard` 对齐或共用（题7） |
| F3 | **缺口清单** | 「要定论还缺什么」（证据、负责人确认、文档未更新……） | 同 F2 |
| F4 | **阻塞与过期提醒** | 步骤过期未动、关键依赖未满足时提醒执行者或 mentor | 截止字段或约定节奏；主路径是提醒还是闸门见题1 |
| F5 | **变更感知（轻）** | 计划文档被改了关键步骤时提示「验收标准可能已变，是否重基线」 | 文档版本或重读 diff；不做自动改标准 |

### 2.4 跟进**不做**什么

- 不替作者改验收标准（谁可改见题8）  
- 不把「群里说过一声」默认当成完成证据（除非题2 把该类信号定为可信）  
- 不做全员无差别巡检（除非题1 明确主路径是定期提醒且有名单）  
- 不与「逼写 RFC」绑死——跟进的是**已有计划**，不是「还没写方案」

### 2.5 触发形态（草案）

| 形态 | 说明 | 适合何时 |
|------|------|----------|
| **对话拉取** | 「看下 XX 方案做到哪了」 | 第一期默认；零新基础设施 |
| **执行者自报** | 「第 3 步环境好了，证据在这个任务/链接」 | 反馈通道 P0 候选 |
| **定期提醒** | cron/触发器催更新缺口 | 仅当题1 选提醒主路径且有对象名单 |
| **事件驱动** | 任务勾选、文档更新推一下对照 | 依赖题2/题3 的信号接入 |

## 3. 验收环节：海豚如何产生价值

### 3.1 价值主张

> **验收 = 对照「执行者（或组织）已认可的计划契约」判定进度与闭环，并给出可行动缺口；不是再跑一遍「RFC 写得规不规范」。**

| | 撰写/审查（已有） | 验收（要补） |
|--|-------------------|--------------|
| 对照物 | 技术方案 SOP（结构+硬闸门） | **这一份计划**里的步骤与成功标准 |
| 问题 | 文档合不合规、建议档位 | **事有没有按计划做成** |
| 典型输出 | SOP 检查报告 + 四档深评建议 | 完成度档位 + 证据等级 + 「定论还缺什么」 |
| 失败模式 | 漏章、动机空话 | 无证据却报完成；双标（两人不同链） |

### 3.2 与 TODO 验收的关系（设计倾向，题7 拍板）

**倾向（与访谈共识一致）：同一套「声明 ↔ 证据 ↔ 档位」引擎，两套投影。**

| 投影 | 契约来源 | 信号来源（例） |
|------|----------|----------------|
| TODO 验收 | 看板格 / 台账条目上的标准 | 任务 `completed_at`、后续填报消失、mentor 评价…… |
| 方案验收 | RFC/清单上的实施步骤与成功标准 | 同上 + 方案文档更新 + 交付物链接 |

禁止：方案线一套「差不多就算」、TODO 线另一套「必须勾选」——同一人同一事两套真相。

可复用已有口径资产：`todo-completion-standard`（四档 + 取证链对称）、`todo-truthfulness-check`（声明-事实，**不等于**验收闭环本身）、`company-todo-audit`（台账闭环）——方案线是**换契约来源**，不是另发明第四套形容词。

### 3.3 验收时海豚具体做什么

| # | 能力 | 说明 |
|---|------|------|
| A1 | **契约锁定** | 验收前确认对照哪一版计划（文档链接 + 步骤列表快照）；标准漂移要显式提示 |
| A2 | **逐条取证** | 按档位规则取 E1/E2/E3 类证据（具体等级名单与 TODO 对齐或在题7 裁剪） |
| A3 | **对称性** | 多人/多步同一深度；某人某级不可用则全体降深并写明（防双标） |
| A4 | **结论形态** | 固定档位表 + 每条依据出处；收尾「要定论还缺什么」；**无反馈 → 无法判定 / 待补报**，不假装通过 |
| A5 | **受众视图** | 执行者看缺口与下一步；mentor/上级看汇总与风险（题8 RACI） |

### 3.4 验收**不做**什么

- 不把「SOP 结构检查通过」当成「方案已验收落地」  
- 不在无进度信号时给出「已完成」  
- 不替代组织正式的上线/立项/HR 流程签章  
- 不在覆盖不足时当作全员考核工具（题5）

## 4. 与已交付能力如何衔接（用户故事串）

1. 中事诉求 → **提醒**可跳过路径（已有）  
2. 起草/打磨 RFC → **撰写检查 + 四档建议**（已有）  
3. 深评通过或作者自认计划可用 → **冻结/引用计划契约**（跟进入口）  
4. 实施期 → **跟进**（F1–F5）：对话或提醒对照步骤  
5. 声称做完或到期 → **验收**（A1–A5）：对照契约给档位与缺口  
6. （可选、暂缓）识别到该写未写 → 监督者二层

## 5. 分期建议（在访谈结论前的工作假设）

| 期 | 目标 | 交付形态（假设） | 依赖访谈 |
|----|------|------------------|----------|
| **P0** | 证明「对照计划跟进/验收」有用 | Skill（或扩展现有 completion 口径）+ 对话触发；计划来自用户给出的 doc 链接或粘贴步骤；进度以自报+已有任务/文档信号为主 | 题1 默认路径；题2 反馈手段；题6 契约最小字段 |
| **P1** | 清单可维护、可复用 | 与「待做清单 / action」最小契约对齐（题4）；定期提醒可选 | 题4 段间契约；题5 非正式定位 |
| **P2** | 更稳信号、更少自报 | 事件/原生 action 覆盖（题3）；与统一数据更深集成 | 题3/题5 门槛 |
| **暂缓** | 监督者二层 | 不排期；强制写方案的产品闸门另议 | — |

**P0 明确 Won't：** 半强制写方案；全员巡检考核；无信号装完成；binding 立项。
