## 1. 预备期

### 1.1 结论先行

**建议做什么**

1. **维持现状（已合入方向 / PR #917）**  
   - **调用面闸门**：工具名不存在 / 空名 / 非法参数等，按**整回合**计，满 **2** 次后拒发并下发恢复文案（对照 live `tools` / schema；点名 `feishu_api`、`browser_call`、`subagent_*`）。  
   - **连续无效闸门**（按工具名）：空串、`error` 开头、「没查到」类文案、空 JSON 信封等，连续 **5** 次后拒该工具名（过渡值，后续可再调）。  
   - **原样重复闸门**：同一 `(工具名, 参数)` 满 **3** 次后拒（由原 5 收紧；合法轮询仍靠「>1」留余量）。  
   - **「有信息后同名再调」**：**只观测、不拒发**（INFO `retry-after-info` + `retry_after_info_count`）。用于证明「模型读完非空结果仍连打同名」的频次，再设计拒发阈值。

2. **下一步不要直接合的行为变更**  
   在观测数据与上级拍板之前，**不要**仅凭「同名再调」拒发工具调用；该闸与合法轮询同形，误伤成本高。

**为什么做**

- 已发生过「换词空搜数百次」「发明 `feishu_*` / 把 MCP 表名当顶层工具」类空转；纯 skill / 提示词不足以结构性收口。  
- 现有「结构空」闸门盖不住「返回非空但业务无关 → 模型仍同名再调」；直接按重复调用拒发又会误伤轮询。需要**分阶段**：先记账 → 再定阈值 / 豁免 → 再拒发。

**需要什么决策（请上级拍板）**

| # | 决策项 | 推荐 | 若不采纳 |
|---|--------|------|----------|
| D1 | PR #917 中调用面闸 + 观测计数是否允许合入 / 继续合 | **允许**（调用面拒发 + retry-after-info 只记） | 仅合调用面、或整 PR 暂缓 |
| D2 | `REPEAT_LIMIT` / `UNPRODUCTIVE_LIMIT` | **已调**：同参 **3**、连续无效 **5**（过渡）；无效闸后续可再调 | 另给目标值与轮询场景重测要求 |
| D3 | 「有信息后同名再调」是否进入**实验期拒发 POC** | **进入实验期设计**，拒发阈值与白名单**实验通过后再实施** | 永久只观测，或改走工具结构化 `pending` 信号 |
| D4 | 拒发闸责任边界 | 继续放在 Session `ToolCallConvergence`（确定性），不以 skill「自觉报无效」为唯一证据 | 另立 workspace 报告工具为主路径（自觉性风险） |

**本期出口**：D1–D4 有明确「通过 / 补证 / 回退」结论后，方可开实验期拒发 POC；**未出口不得把观测计数升级为拒发并当默认行为发布。**

### 1.2 目标用户与问题依据

| 角色 | 问题 | 依据类型 |
|------|------|----------|
| 飞书 / SPA 终端用户 | 对话长时间「在干活」却无结论；或重复无意义工具调用 | **事实**：生产曾出现同工具换词空搜至上游 402（见 `tool_convergence` 模块说明）；调用面猜名导致连续 `Tool not found` |
| 部署 / 值班 | 单回合烧满 `max_tool_rounds`，延迟与费用上升，日志难归因 | **事实**：回合收敛日志与 `ai-turn` / tool `elapsed_ms` 可观测；**推断**：非空错结果重试会拉长墙钟 |
| Agent 能力包作者 | skill 写了「勿发明工具名」仍被连打 | **事实**：提示词无法阻止错误 `tool_calls` 发出；硬闸在 Session |

**事实 / 推断 / 待验证（分开）**

- **事实**：工具结果在 Session 内是字符串；`is_unproductive_result` 只认固定「空/失败」形状；「有字段但无关」不算空，且会清零该工具连续无效计数。  
- **事实**：模型是否再调同一工具，由模型读 history 后自行决定；运行时**没有**「空了才允许再调」的白名单，只有触顶后的黑名单拒发。  
- **推断**：「有信息后同名再调」多数时候表示模型认为上轮不够用（含合法轮询与无效死磕两种）。  
- **待验证**：生产 / 预发里 `retry-after-info` 的分布（按工具名、count 直方图）；其中多少是 `background_*` / 状态轮询，多少是看板读写类死磕。

### 1.3 价值主张

| 维度 | 内容 |
|------|------|
| **客户价值** | 更少无效连打 → 更快得到「查不到 / 需补充线索 / 换路径」的诚实结论；降低单会话费用与排队延迟。 |
| **为什么是我们** | 空转发生在 **Session agent loop**（工具执行前后），只有内核收敛能在「发出前」拦住；channel / SPA 只能事后看流。已有三闸 + 调用面闸的同构扩展点在 `ToolCallConvergence`。 |
| **怎么最快验证** | （1）合入观测计数，采 1–2 周 INFO；（2）用历史 JSONL / 定向 DEBUG 回放「非空仍同名」样本；（3）小流量拒发 POC + 轮询白名单 A/B。 |
| **投入产出** | 观测：已落地，边际成本 ≈ 日志量。拒发闸：约 1–2 人日设计 + 单测/变异复核 + 预发观察；误伤回退成本低（关阈值或加白名单）。相对「靠人改 skill」可复利。 |

须指回下方对照块：相对「只改 skill」和「业界通用 agent 框架默认不管 tool 空转」，我们选**内核确定性闸门 + 分阶段观测**。

### 1.4 资料与友商对照

| 对象 | 有什么 | 缺什么 | 可复用? | 要自建? | 对本方案含义 |
|------|--------|--------|---------|---------|--------------|
| 本仓现状（`tool_convergence`） | 连续无效 / 原样重复 / 调用面拒发；结果须声明「未执行」 | 「非空但没用」无硬闸；无生产分布数据 | **直接用**为底座 | **部分**：仅增观测与后续拒发层 | 不另起框架；在现计数器旁加第四类 |
| PR #917 调用面闸 | 猜名/坏参回合级封顶 + skill「调用面约束」 | 不覆盖业务半成功重试 | 直接用 | 否（已实现） | 预备期认定「编工具名」路径可先收口 |
| 仅 skill / 提示词 | 零代码、迭代快 | 模型可不遵守；无计数无拒发 | 改造为辅 | 否作为主路径 | 对照说明：不能替代 D3 的硬闸 |
| 「模型调 report_dead_end 工具」 | 语义精确（模型亲口说无效） | 靠自觉；漏报则闸不涨 | 改造接入（可选辅路径） | 部分（若实验需要） | 备选，不作本期主推荐 |
| Cursor / 常见 IDE Agent | 有轮次/工具上限类护栏（形态各异） | 无公开、可逐字复用的「空搜 / 猜名」产品化方案 | **不可用**（闭源、协议不同） | 否 | 「业界最强」不可直接采购；可对标「硬上限 + 对用户说明」 |
| 裸 OpenAI tool loop | 无收敛，靠应用层自写 | 无现成闸 | 不可用 | 是（我们已自建） | 证明缺口在应用 / Session，不是模型 API |
| 工具自报 `pending` / `empty` / `actionable` | 判据确定、误伤低 | 要改大量 workspace 工具契约 | **部分**（新工具优先） | 部分（长期） | 与「同名再调」正交；实验期应并列评估 |

**为什么这么写**：空转是 Session 结构问题，对照后主路径只能是内核闸门；友商/IDE 无现成可采购模块，故自建收敛层合理。  
**为什么有价值**：相对只写 skill，确定性拒发能改变用户任务结果（少空转、少 402、少烧满轮次）；观测阶段把误伤风险留在实验期，避免预备期就锁死错误阈值。

### 1.5 实施路径（现状 → 目标）

```text
现状
  ├─ 已有：UNPRODUCTIVE / REPEAT(5) / CALL_SURFACE(2)
  ├─ 已有（#917）：retry-after-info 只记 + INFO
  └─ 缺口：非空仍同名死磕；拒发阈值与轮询豁免未定

路径
  1) 预备期评审（本文）→ 冻结 D1–D4
  2) 实验期：采 retry-after-info 分布；设计阈值 / 白名单 / NOTICE；POC 拒发（可开关）
  3) 实施期：默认开启或按部署开关；单测 + 变异复核 + AGENTS 钉死
  4) 跟进验收：空转相关回合占比、误伤工单、回退次数

目标结果
  - 猜名空转：调用面闸持续有效（已覆盖）
  - 同参连打：REPEAT=3（由 5 收紧；轮询余量仍 >1）
  - 结构空换词：无效闸 UNPRODUCTIVE=5（过渡，可再调）
  - 非空仍同名死磕：有数据支撑的拒发策略（实验通过后）
```

### 1.6 核心决策点

| 议题 | 选项 | 推荐 | 理由 |
|------|------|------|------|
| 原样重复阈值 | **降到 3** / 保持 5 / 取消 | **降到 3** | 收紧同参死磕；轮询仍留 3 次余量，误伤用观测复核 |
| 第四闸信号源 | 仅同名再调 / 模型 report 工具 / 工具结构化字段 | **先同名再调观测**；拒发设计时并列评估结构化字段 | 同名再调零改工具面、立刻有信号；结构化更准但改造面大 |
| 拒发范围 | 按工具名 / 按回合 / 仅非空后同名 | **仅「上轮有信息后的同名再调」**（与空结果闸正交） | 避免与 UNPRODUCTIVE 双计；空信封仍走旧闸 |
| 轮询 | 无豁免硬闸 / **白名单或更高阈值** / 要求 args 含 poll 标记 | **白名单或更高阈值**（实验期钉名单） | 纯同名计数必误伤；名单可演进 |
| 主路径 | 复用 `ToolCallConvergence` / 新建独立模块 / 只做 skill | **复用** | 与现三闸同生命周期（per `run()`）、同拒绝文案前缀约定 |

**复用 / 采购 / 自建**：无外部可采购等价组件 → **自建**在现有收敛模块内；**复用**本仓已有闸门与 NOTICE 模式；不采购闭源 IDE 行为。

## 2. 实验期（待预备期出口后执行）

> 本节为实验计划骨架；**数字多为待验证**，出口前须补齐同口径样本。

### 2.1 差异化量化对比与测评（计划）

| 对比对象 | 口径（建议） | 基线 | 目标（待定） |
|----------|--------------|------|----------------|
| 无调用面闸 | 同 prompt 下猜名连打次数至停 | #917 前行为 / 单测固定 mock | 满 2 次 call-surface 后停止换名 |
| 仅观测 vs 观测+拒发 | 同会话集：同名再调次数、是否误伤轮询、用户可见半截回复数 | 观测期 1–2 周 `retry-after-info` 直方图 | 待验证：拒发后死磕回合下降 ≥X%，轮询误伤 ≤Y 单/周 |
| REPEAT=3 vs 更低 / 无效闸=5 | 轮询工具成功完成率；空搜拒发是否过早 | 现网 / 预发 `background_*`、读状态类 | **待验证**；无效闸后续可再调 |

**Test Task（实验期）**

1. 单元：已有 `test_tool_convergence`（空 / 重复 / 调用面 / retry-after-info 只记）。  
2. POC：fixture 会话「非空错结果 → 同名再调 N 次」在候选阈值下的拒发文案与是否误伤并行同波调用。  
3. 日志抽检：预发 `retry-after-info` 按工具 Top-N。

### 2.2 正反反驳

| 质疑 | 回应 |
|------|------|
| 「同名再调就是正常轮询，一闸就伤」 | 故本期**只观测**；拒发必须带白名单或更高阈值；预备期写明误伤是第一风险。 |
| 「有调用面就够了」 | 调用面不管合法工具 + 非空无关结果；生产空转不全是猜名。 |
| 「把 REPEAT 降到 2 更简单」 | 与轮询同形；模块注释与事故设计都按 5 留余量；**本方案冻结保持 5**。 |
| **最坏情况** | 拒发阈值过紧 → 合法等待任务失败、用户以为产品坏了。**代价**：紧急配置关闸或抬高阈值；稳定版回退到「只观测 + 旧三闸」。 |

### 2.3 备选方案（含业界最强 / 不做）

| 备选 | 考察结论 |
|------|----------|
| **不做**第四闸 | 否掉为唯一长期方案：非空死磕仍靠 `max_tool_rounds`，用户体验与费用问题保留 |
| **直接采用业界最强**（照搬某 IDE Agent 收敛） | 否掉：无开放、可合规迁入的实现；协议与 tool 面不同 |
| 只加强 skill | 否掉为主路径：无法阻止错误/固执 `tool_calls` |
| 模型 `report_tool_dead_end` | 保留为辅；不作唯一证据（漏报） |
| 全工具改结构化 `actionable` | 长期优、短期面过大；实验期可对**高频肇事工具**试点，不阻塞观测 |

### 3.2 验收标准（技术 · 草案）

| 类 | 内容 |
|----|------|
| **测试** | 主路径：猜名满 2 拒；空结果满 5 拒；同参满 3 拒；retry-after-info 计数正确且**当前不拒**。异常：拒绝 NOTICE 不回灌计数。回退：关第四闸后行为 = 旧三闸 + 调用面。 |
| **Critical 指标（待验证钉死）** | 例如：含「工具空转」特征的回合占比下降；call-surface / unproductive 拒发后模型改路径或诚实收束的比例。 |
| **护栏** | 轮询类工具完成率不显著下降；单回合 P95 延迟不因误拒重试策略而恶化到不可用；日志量可接受。 |
| **观察周期** | 建议预发 ≥1 周，再决定默认开。 |

### 3.3 风险与回退

| 风险 | 停止线 | 降级 | 稳定版本 |
|------|--------|------|----------|
| 轮询误伤 | 误伤工单 > 约定阈值 | 加白名单 / 抬阈值 / 关拒发 | #917：调用面 + 旧闸 + **只观测** |
| 双计（空 + 再调） | 单测出现同一次结果推高两闸异常 | 再调闸仅在 `_last_had_info` 为 True 时计（已如此） | 同上 |
| NOTICE 被模型当「又一次空」 | 变异复核失败 | 文案强调「未执行 / 须重审任务」 | 对齐现有 `REFUSAL_PREFIX` 模式 |

### 3.4 非目标与展望

**非目标（本期）**

- 不解决跨回合分散重试（计数器 per `run()`，刻意为之）。  
- 不替代 `max_tool_rounds` 总上限。  
- 不改造全部飞书工具契约为结构化状态（可展望）。  
- 不把 SPA / 飞书 UI「停止」语义改成新协议。  
- **不在本预备期稿通过前，把 retry-after-info 升级为默认拒发。**

**展望**

- 高频工具 `actionable` / `pending` 字段与再调闸联动。  
- 可选辅路径：`report_tool_dead_end`。  
- 观测仪表：按工具聚合 retry-after-info。
