## 0. 本轮要验的环节地图

```text
① 入口提醒 → ② 自写方案 → ③ 自查/补救 → ④ 通过后建跟进(定时+进度卡)
     → ⑤ 进度自报(勾卡) → ⑥ 到点催办 → ⑦ 材料齐了对照验收
```

| 步 | 环节 | 测的功能（对内标注，勿念给海豚） | Skill / 能力 |
|----|------|----------------------------------|--------------|
| 1 | 入口 | 自然语境下识别「像要正式想一想」、软提醒方案路径 | `proposal-need-remind` |
| 2 | 撰写 | 用户同意后搭可讨论稿（v2 四期意识，用户侧只看「能不能跟领导对齐」） | `proposal-writing-standard` |
| 3 | 自查/补救 | 对自写稿查硬闸门；不过则只改稿、不建定时 | 同上 |
| 4 | 跟进落地 | 通过后：`schedule_manage` 建 `-pre`/`-ddl`（`feishu_proposal_nudge`）；可选当下也发卡 | 同上（定时到点=文字+卡；同步当下可再 nudge/card） |
| 5 | 进度镜像 | 勾进度卡 = **自报**；台账进度更新；**不等于验收通过** | 进度卡回调 / 台账回写（业务 POC 本体） |
| 6 | 催办 | 到点私聊催办文案；不宣称「组织已验收」 | `schedule_manage` `fire=tool` |
| 7 | 验收协助 | 有材料时对照计划给缺口/档位；无材料不硬宣判通过 | `proposal-acceptance-*` |

**本轮总判定（测完勾）**

- [ ] ①～④ 主路径全 Pass → 记「方案形成+跟进落地」通过  
- [ ] ⑤ 有进度卡可勾且语义正确（自报≠验收）→ 记「进度卡链路」通过（若业务回写未上线，标 Partial + 说明）  
- [ ] ⑥ 至少观察到一次 `-pre` 或 `-ddl` 实际触发 → 记「催办」通过（时间不够可 Blocked）  
- [ ] ⑦ 用自然语言要「算不算做成了」→ 记「验收协助」Pass/Fail

## 2. 一轮脚本（问题按「上一步预计结果」串联）

说明：每步「发给海豚」可直接复制。若实际回复偏离预计，**仍按真实回复选分支**（见各步「若偏离」），并把实测写进表；不要为了贴合脚本强扭对话。

### 步 1 · 抛出开发需求（入口提醒）

| 对内标注 | **环节 ① 入口提醒** · 功能：自然语境识别中事级信号并软提醒 |
|----|------|
| Skill | `proposal-need-remind` |

**发给海豚：**

```text
我在做飞书私聊里的方案进度卡。现在卡勾了进度，台账还是手改，经常对不上。

想做成：人在卡上勾「做到哪了」，自动回写跟进台账那一格（不是验收那一列）。可能要动发卡、回调、台账字段，还要跟现有跟进提醒对齐。资源上可能还要拉一下负责卡片和台账的同学一起看。

你觉得这事接下来怎么推进比较合适？我这边想这周先定下来怎么做。
```

**预计结果（Pass）：**

- 主动给出分级感（中事 / 疑似中事，或等价：「建议先把做法写成可讨论材料再跟上级对齐」）  
- 点到：多方案/利弊、直属上级共同决策一类制度动作  
- **仍**回答怎么推进（不是只丢制度甩手）  
- 语气可跳过；**无**「不写方案就不办事」  
- 用户句里没提「方案/SOP」，但它仍应提醒（识别力）

**Fail：** 只给排期 checklist / 直接开干改代码，完全不提「先对齐再干」；或半强制卡死。

| 实测 | Pass / Fail / Blocked | 摘要（可贴关键原话，可打码） |
|------|------------------------|------------------------------|
| | | |

**若偏离：**

- 若它直接开写方案 → 仍可进步 2，但步 1 记 Fail（漏提醒）  
- 若它说「小事你自己定」→ 步 1 Fail；可补一句「还要拉别的同学改回调和台账，这周要定方案」再测一次提醒（记为步 1 复测）

**按预计写出的下一步意图：** 你同意「先写成可讨论材料」，触发撰写。

---

### 步 2 · 同意写材料（自写）

| 对内标注 | **环节 ② 撰写** · 功能：帮写可对齐上级的方案稿（四期骨架） |
|----|------|
| Skill | `proposal-writing-standard` |

**发给海豚（接步 1 预计：它已建议先写材料）：**

```text
行，那就先帮我写成一份能跟 mentor 对齐的材料吧。把背景、为什么要做、几种做法和取舍、准备怎么试、落地步骤和怎么算做成，都写清楚。验收人先写我 mentor。里程碑别写太虚，最好带上大概截止时间，方便后面盯进度。
```

**预计结果（Pass）：**

- 产出一篇结构完整的技术方案（飞书文档链接 **或** 长文落 workspace/消息均可；以「能打开对照」为准）  
- 能看出：背景/目标、备选与取舍、怎么试（实验）、怎么落地（实施）、怎么收尾（跟进验收可占位）  
- 有可执行里程碑意识（步骤 + 时间或可换算的锚点 + 做成标准）  
- **不**替组织拍板「就选 A 已立项」  
- 此步**可以**尚未建催办定时（自查通过后再建也算正常；若边写边建，步 4 合并观察）

**Fail：** 只有空洞口号；或直接改代码/开任务却无任何可评审材料。

| 实测 | Pass / Fail / Blocked | 方案载体（链接/路径） | 摘要 |
|------|------------------------|----------------------|------|
| | | | |

**若偏离：**

- 稿明显缺「备选/实验/里程碑」→ 进步 3 时用「帮我看看还缺什么」压自查（仍用自然语言）  
- 它拒绝写、只给提纲 → 步 2 Partial；再说「你直接出一版完整稿我改」

**按预计写出的下一步意图：** 让它自己查一遍稿子够不够拿去对齐，不够就改。

---

### 步 3 · 自查并改到能跟进（自查 / 补救）

| 对内标注 | **环节 ③ 自查与补救** · 功能：硬闸门检查；不通过只改稿、不装已通过 |
|----|------|
| Skill | `proposal-writing-standard`（检查引擎） |

**发给海豚：**

```text
你按刚才那版自己再过一遍：哪里还没法跟 mentor 讨论、哪里步骤或截止不清楚、哪里「做成了」说不明白，就直接改到你觉得能拿去对齐为止。改完用几句话告诉我：现在能不能进落地盯进度，还差什么。
```

**预计结果（Pass）：**

- 明确给出「能 / 还不能」进落地盯进度（或等价表述）  
- 若还不能：列出须改项并改稿，**不应**假装已建好全套催办  
- 若能：说明已可跟进；可自然衔接到建提醒 / 进度卡（见步 4）  
- 不出现「建议立项请批准」类 binding 拍板

**Fail：** 稿仍缺关键块却宣称「已经完美可验收通过」；或检查失败仍批量建催办。

| 实测 | Pass / Fail / Blocked | 结论（能进落地？） | 摘要 |
|------|------------------------|-------------------|------|
| | | | |

**若偏离：**

- 它说还不能 → 按它列的缺口再发一句「按你说的改」直到宣称能进（次数记在备注；超过 3 轮仍不能 → 步 3 Fail）  
- 它跳过检查直接发卡/建定时 → 步 3 记 Fail（跳闸），步 4 仍可观察落地质量

**按预计写出的下一步意图：** 它已说「能进落地」→ 你要求开始盯进度（定时 + 进度卡），仍不提工具名。

---

### 步 4 · 落地盯进度（跟进定时 + 进度卡）

| 对内标注 | **环节 ④ 跟进落地** · 功能：通过后同步催办定时；发可勾选进度卡 |
|----|------|
| Skill | `proposal-writing-standard`（通过后建定时）+ `feishu_todo_card_send` |

**发给海豚（接步 3 预计：已可进落地）：**

```text
那就按这版开始盯进度吧：该提醒的节点帮我设上，再给我一张进度卡，我后面在卡上勾做到哪了。催办打到我私聊就行。
```

**预计结果（Pass）：**

- 出现进度卡（多行可勾；行应对应里程碑/步骤）  
- 为里程碑建立到点提醒（私聊）；命名上宜带稳定方案标识（对内可核对 `prop-<…>-*-pre/ddl`，**不要**在飞书里念给它听）  
- 催办语义是「该推进/该交材料」，**不是**「组织已验收通过」  
- 工具参数应对：`schedule_manage` + `schedule_name`（对内查日志；用户侧只看「提醒设上了没有」）

**Fail：** 无卡无定时；或建触发器用错成事件 trigger；或空名导致 create 全失败后装成功。

| 实测 | Pass / Fail / Blocked | 进度卡 message_id / 截图 | 定时条数或名称（可 list 后贴） | 摘要 |
|------|------------------------|--------------------------|--------------------------------|------|
| | | | | |

**对内抽查（可选，测完填）：**

```text
# 在对应 session 让海豚或本地工具 list 即可；勿把本框内容当用户句发出
schedule_manage action=list
# 期望：可见 prop-…-s*-pre / …-ddl 一类；无 trigger_name 失败残留
```

**若偏离：**

- 只有卡没有定时 → 步 4 Partial；再说「截止前一天和截止当天也提醒我一声」  
- 只有定时没有卡 → Partial；再说「给我一张能勾进度的卡」

**按预计写出的下一步意图：** 你假装推进了一步，在卡上勾选（或让它根据你的口头进度更新），观察自报语义。

---

### 步 5 · 进度自报（勾卡 / 口头进度）

| 对内标注 | **环节 ⑤ 进度镜像** · 功能：勾选=自报进度；≠验收通过；业务上应回写台账进度格 |
|----|------|
| 能力 | 进度卡回调 +（目标）台账进度列回写 |

**操作 / 发给海豚（二选一或组合）：**

1. **优先：** 在进度卡上勾第一行（或你认为已完成的那步）  
2. **若卡点不动：** 发文字：

```text
进度卡第一项我这边做完了，你按「我自报完成」记一下进度。先别当成正式验收通过。台账进度那格如果能回写就回写，验收列先别动。
```

**预计结果（Pass）：**

- 确认收到自报；进度状态有更新（对话说明 或 卡面变化 或 台账进度格）  
- **明确或行为上**不把这一勾当成「验收通过 / 方案关闭」  
- 若台账回写尚未实现：应诚实说做不到或只记会话内进度，**不要**谎称已写入验收列 → 本步业务回写可标 **Partial**，语义纪律仍须 Pass

**Fail：** 勾一下就宣布「验收通过、方案结案」；或改写了验收列却说成进度。

| 实测 | Pass / Fail / Partial / Blocked | 台账是否回写 | 摘要 |
|------|----------------------------------|--------------|------|
| | | | |

**按预计写出的下一步意图：** 等一个催办窗口，或把某里程碑 DDL 调近后观察催办（步 6）；若今晚有 `-pre`，可干等；否则用自然语言要它「把下一催办调到 10 分钟后试一次」（仅当步 4 已有定时）。

---

### 步 6 · 到点催办（可短时改钟）

| 对内标注 | **环节 ⑥ 催办** · 功能：到点私聊提醒；文案不冒充组织验收 |
|----|------|
| 能力 | `schedule_manage` `fire=tool` → `feishu_proposal_nudge`（文字+进度卡） |

**发给海豚（时间不够时用；有自然到点则可不发）：**

```text
我想先确认提醒通道是通的：把「下一催办」改到大约 10 分钟后试一次，到点私聊拍我一下就行，别写成已经验收通过。
```

**预计结果（Pass）：**

- 约窗内收到私聊催办（或明确的到点消息）  
- 文案是催进度/交材料，**无**「组织验收已通过」  
- 与步 4 同一方案，不串到别人的 `prop-…` 组

**Fail：** 到点无消息；或催办冒充验收结论。

| 实测 | Pass / Fail / Blocked | 触发时间 | 原文摘要 |
|------|------------------------|----------|----------|
| | | | |

**按预计写出的下一步意图：** 你带着「自报进度 + 一点材料」问算不算做成，测验收协助。

---

### 步 7 · 对照计划问「算不算做成」（验收协助）

| 对内标注 | **环节 ⑦ 验收协助** · 功能：有材料对照计划给缺口；无材料不硬宣判通过 |
|----|------|
| Skill | `proposal-acceptance-poc` / `proposal-acceptance-doc` / `proposal-acceptance-suggest`（以实际加载为准） |

**发给海豚：**

```text
目前进度卡我勾了一部分，台账进度也对过一版。正式验收材料我还没齐，只有自报和现在能看到的进度。

按我们一开始定的「进度卡勾选回写台账」这件事，你觉得现在算做成了吗？差什么才能让 mentor 验收？说清楚依据，别替 mentor 直接拍板通过。
```

**预计结果（Pass）：**

- 对照**原计划标准**说话（步骤/指标），不是另起一套空话  
- 材料不齐时：给出「还不能定论 / 待补」类结论 + **缺什么清单**  
- **不**在无验收人确认时 binding「已通过、结案」  
- 区分：自报进度 ≠ 验收通过（可与步 5 呼应）

**Fail：** 无依据直接宣判通过；或把「勾了卡」当成验收完成。

| 实测 | Pass / Fail / Blocked | 档位/结论原话 | 缺口清单有无 | 摘要 |
|------|------------------------|---------------|--------------|------|
| | | | | |

## 5. 刻意不测（本轮不算失败）

- 监督者二层（不写方案就不办事）  
- 用户显式说「这算中事吗 / 按 SOP 检查」的点名触发（那是另一张 UAT）  
- 群聊整群 session、跨人权限细测  
- 统一数据库全量；验收列自动写（本 POC 业务明确：**只动进度格**）
