## 一句话

TODO 那套是「公司 SOP → skill 五段（规范即配置）→ 多轴判定 → 飞书载体」。  
技术方案评估用**同一模式**，换 schema/规则/载体；**不搬**周期填报、请假、看板缺写那条线。

## 和 TODO 的异同（速查）

| | TODO（已有） | 技术方案（要做） |
|--|--|--|
| 规范形态 | 三层：大目标/小目标/TODO | RFC 头 + 11 章固定顺序 |
| 质量判定 | 按时/按质/按量/mentor check | 结构齐全 + 硬闸门（动机/缺点/备选/数据诚实） |
| 载体 | 看板表（人×日期）+ 台账 + 卡 | **飞书文档 / wiki 里的 RFC** |
| 节奏 | 周一三五 cron | 对话/提交触发为主，少定时 |
| 完成语义 | 任务勾选 + 五要素闭环 | 评审拍板（做/不做/怎么做），不是 tick |
| 可复用 | 五段 skill、分轴、引擎不写死口径 | 同左 |
| 别搬 | — | `fill-check` / leave_query / sync·audit 全家桶 |

`todo-writing-standard` 已写伏笔：演进「小方案」时与方案 SOP 共享 schema 机制。方案检测**先独立 skill**，别缠进周期 TODO 管线。

## 要落什么（第一版够用就行）

### 1. `proposal-writing-standard`（名可改）

对标 `todo-writing-standard`，五段：

| 段 | 内容 |
|--|--|
| schema | RFC 头（Feature Name / Start Date / PR·Issue / Status）+ 11 章顺序 |
| 规则集 | 见下「硬闸门」 |
| 载体 | 飞书 docx/wiki；读 `feishu_doc_read` / `get_node` |
| 参数 | 术语、报告文案、可选豁免条件 |
| 引擎 | 帮写 / 检查 / 补救；**不写死章节名和数字** |

**规则集（从 SOP 抽）：**

1. 结构：11 章顺序在；参考层可 N/A；无有效性主张时可省略「数据集和预实验」，其余章不可删。  
2. 动机闸门：一句话「谁 / 场景 / 痛点 / 验收人」；禁「降本提效智能化」空话。  
3. 诚实闸门：缺点要具体；说不出缺点 = 违规。  
4. 决策闸门：关键选择至少有一个被否掉的备选。  
5. 证据闸门：声称更好/有效 → 要有数据或明确「待探索」；无来源数字标 `[待调研]`，不编造。  
6. 写法（软）：总结可验证、精炼——报告里提示即可。

能力：帮写草案、按规则检查、给出缺章/违规项 + 依据、可选补结构缺口（**不替人拍「做不做」**）。

### 2. `proposal-review-standard`（名可改）

对标完成度/评价口径，**另写档位**，勿套用「已完成/未闭环」：

建议档位（可改）：

- 可立项 / 进入深评  
- 需补齐后重提（列缺口）  
- 叫停·动机不过  
- 待人工深评（模型吃不准）

每条结论必须点到章节 + SOP 硬规则。

### 3. 第一版不做

- 周期看板缺写、请假免填  
- Bitable 台账 + sync/audit 全家桶  
- 替评审人最终拍板  
- 评价卡（有需要再挂，对标 `company-todo-review`）

## 主流程

```text
「按技术方案 SOP 检查这篇」/「帮我起草方案」
  → 读飞书文档
  → 按 schema 拆章 + 按规则集逐条判
  → 报告：通过项 / 违规项（缺哪章、哪条硬规则）
  → 可选：补草案结构；人改方向后再检查
  → 可选后期：Status=待审核 + 通知验收人
```

***

## 落地顺序

1. 写 `proposal-writing-standard` 五段 skill（SOP 进 schema/规则集）  
2. 写 `proposal-review-standard`（档位 + 报告模板）  
3. ~~用 RFC-0001 或真实方案手跑 1–2 次看报告好不好用~~（待业务手跑）  
4. **提醒者一层** `proposal-need-remind`（2026-09-03）：按公司大事/中事/小事，对话里疑似中事则软提醒写方案；不扫表、不半强制  
5. （未做）监督者二层：较可靠识别 + 半强制要求写出方案  
6. 再决定评价卡 / Status 回写 / 批量巡检（无方案表则长期不做定期扫描）

***

## 决策分级与方案入口（两层）

| 层 | Skill | 行为 |
|----|-------|------|
| 提醒者 | `proposal-need-remind` | 疑似中事 → 建议写多方案；大事 → 会议集体决策；可跳过 |
| 撰写检测 | `proposal-writing-standard` | 读/检/帮写/补救飞书云文档 |
| 评审建议 | `proposal-review-standard` | 四档建议，不替人拍板 |
| 监督者 | （未做） | 半强制写方案 |

制度要点：中事 = 拟定方案（多种方案+分析）+ 直属上级共同决策；小事个人决策；大事会议民主讨论、第一责任人拍板。
