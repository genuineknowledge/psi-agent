# 招聘记录补充与更正

仅更新现有招聘记录。必须调用 `recruitment_update_record`，并且只依据它返回的脱敏
结果判断写入是否成功。

## 执行顺序

1. 从用户原话提取目标表、明确字段和值，不补写用户没有给出的业务判断。
2. 定位顺序固定为：上下文中已有的 `record_id`，其次是用户给出的飞书行链接，最后才是
   `姓名` 精确匹配。不要让用户重复提供已经存在于可信上下文中的记录 ID。
3. 调用 `recruitment_update_record`。`updates_json` 只传本次明确要求修改的字段；不要为了
   “补全记录”带上其他字段。
4. 只读取工具返回的 `ok`、`target`、`matched_by`、`fields` 和 `message`。`ok=true`
   才能告知用户已写入并完成读回核验；`ok=false` 时必须说明未确认成功，并按 `message`
   请求用户补充定位信息或稍后重试。

## 安全边界

- 不要求、接收或传递 app token、table ID、`user_key` 或 identity。目标资源只由运行时
  workspace 的固定招聘配置决定；行链接也只能用于提取记录 ID。
- 姓名匹配为零行时不写入；匹配多行时不猜测。请用户提供对应飞书行链接消歧。
- 不推断评分、初审状态、面试状态、定级、风险结论、录用结论或任何 Human 决策。
  用户只给事实说明时，只写入其明确指定的文本字段。
- 不绕过本工具调用通用飞书写接口，也不根据异常、原始响应或先前 Workflow 输出自行宣称
  写入成功。
- 本能力只做现有行的补充和更正，不创建人才库行或面试记录行；创建仍由招聘 Workflow
  负责。

## 字段提示

- 人才库：`备注`、`初审状态`。
- 面试记录：面试纪要、补充信息、四项明确评分、面试定级、聪明人等级、疑问待验证、
  风险验证结果、面试结论、面试状态、面试时间。
- 四项评分必须是用户明确给出的整数 1-5。面试时间必须包含时区；信息不完整时先追问，
  不自行选择默认值。
