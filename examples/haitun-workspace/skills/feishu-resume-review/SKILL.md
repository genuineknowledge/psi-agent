# 简历审核（评估 + 面试建议）

对**一份**简历做：事实抽取 → 分项评分 → 综合评价 → 面试提问建议。  
可选：用户给出飞书多维表时，按表列写入一行。

本 skill 是简历域的**默认底座**。用户补充/修改评分标准、面试题偏好、岗位 JD 对齐规则时：  
先 `skill_manage list/view`，命中本 skill 后 **`patch` 更新**，禁止再 `create` 平行「简历-xxx」skill。

## When to use

- 用户交来简历（聊天附件 / 本地路径 / 飞书 doc / PDF），要评估、打分、出面试题。
- 说法类似：评估这份简历、审一下候选人、给面试建议、简历入库到某张多维表。

## When not to use

- 纯排版/OCR、不涉及判断（只转文字）→ `ocr-and-documents` / `read`。
- 与简历无关的招聘流程配置、触发器（用对应 skill / `trigger_manage`）。
- 用户只问「怎么写简历」的写作辅导（非审核）。

## 输入（缺就问，别猜）

1. **简历材料** — `[RECV:]` 路径、本地路径、或飞书文档链接。
2. **（可选）目标岗位 / JD** — 有则按 JD 加权；无则用下方默认量表。
3. **（可选）飞书多维表** — `app_token` + `table_id`，或可解析的 base 链接；无表则只在对话/文档里交付评估结果。

## 列语义（有表时）

先 `feishu_bitable_list_fields`，按列名语义填，不写死表结构：

| 类型 | 例 | 做法 |
|------|-----|------|
| **A 事实** | 姓名、电话、邮箱、学校、学历、年限 | 从简历抽取；没有就空，不编造 |
| **B 判断** | 科研、项目、综合评分、评价、优劣势 | 按「评分规则」；无对应列则写在对话交付物里 |
| **C 面试** | 面试题、建议提问 | 按「面试提问建议」 |

## 流程

1. **读简历**：PDF/扫描优先文本层（`read_pdf` / PyMuPDF）；空则 OCR skill；飞书 doc 用 `feishu_doc_read`。
2. **抽事实**：姓名/联系方式/教育/工作/项目/证书等；不确定标「简历未写明」。
3. **评分 + 评价**：按下方量表打分，写综合评价（见输出模板）。
4. **面试题**：按下方规则出 4–6 道贴合简历的题。
5. **（可选）写表**：组装 `fields_json` → `feishu_bitable_create_record`（或已有同人行则 `update_record`）。
6. **交付**：对话里给出结构化结果；若写了文件用 `[SEND:]`。

## 评分规则（默认底座；用户规则优先 patch 进本节）

满分按维度 1–5（5 优）。无 JD 时用默认权重；有 JD 时先对齐硬性要求（学历/年限/栈），不满足在评价里写明。

| 维度 | 看什么 | 权重（默认） |
|------|--------|--------------|
| 教育背景 | 学历层次、专业相关度、学校与岗位匹配 | 15% |
| 相关经验 | 年限、职责与目标岗重叠、晋升/责任变大 | 30% |
| 项目/成果 | 是否可核验的结果（指标、上线、规模），而非空形容词 | 25% |
| 技能匹配 | 硬技能/工具与 JD 或常见岗要求重合度 | 20% |
| 表达与完整度 | 时间线清晰、无硬伤空窗无解释、表述可核查 | 10% |

综合分 ≈ 加权平均（保留一位小数）。档位：

- **推荐面试** ≥ 3.8  
- **可考虑** 3.0–3.7  
- **暂不推荐** < 3.0  

硬性否决（出现则档位不得高于「可考虑」，并在评价首句写明）：明显造假迹象、关键经历与时间线矛盾、目标岗必备资质明确缺失。

**评价写法（必出）：**

1. 一句话结论（档位 + 综合分）  
2. 3 条优势（贴简历事实）  
3. 2–3 条风险/待核实  
4. 若有 JD：与 JD 的匹配摘要（命中 / 缺口）

用户补充的公司量表、一票否决、岗位族权重 → **patch 本节**，不要另建 skill。

## 面试提问建议（默认底座；用户偏好 patch 进本节）

出 **4–6** 道题，必须能在简历里找到锚点（项目名/公司/技术/成果数字）：

| 类型 | 数量建议 | 目的 |
|------|----------|------|
| 深挖项目 | 2 | 核实成果、个人贡献、难点 |
| 技术/专业 | 1–2 | 验证声称的技能深度 |
| 行为/协作 | 1 | 冲突、推进、跨团队 |
| （可选）动机/稳定性 | 0–1 | 仅当简历有跳槽密集或转行时 |

禁忌：通用空题（「做个自我介绍」）、与简历无关的题、诱导编造。  
每题附一行「考察点」。用户指定题型/题量/禁用题 → **patch 本节**。

## 输出模板（对话）

```text
## 简历评估
- 候选人：…
- 综合分：x.x / 5（档位）
- 分项：教育… | 经验… | 项目… | 技能… | 完整度…

### 综合评价
…

### 建议面试题
1. …（考察点：…）
…
```

## Boundaries

- 不编造简历没有的学历、公司、业绩数字。
- 评估是招聘辅助意见，不是录用决定；涉及录用/拒信由人拍板。
- 更新本 skill 用 `skill_manage(action="patch")`（`agent_editable: true`）；禁止平行 create。
- 写飞书表前确认 `app_token`/`table_id`；缺凭证时说明，仍可交付对话评估。
