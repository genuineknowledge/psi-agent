# TODO 填报规范检查(15:00)

## 数据源(定时触发没有对话上下文,参数必须写全)

| 数据源 | 参数 |
|---|---|
| 团队 TODO 看板表 | 链接 https://genuineknowledge.feishu.cn/wiki/H6icwLWn1iwpXAk73QMcA6MgnWc —— /wiki/ 链接先 `feishu_api` GET /open-apis/wiki/v2/spaces/get_node 换 obj_token,再读表;表结构(表头行/人名列/mentor 列/最新日期列)每次现场探,不写死 |
| 请假事实 | `feishu_leave_query`,approval_code=`99EEC396-536A-4C7A-8B2D-412584E35CE3`(只算已通过;审批中/读不出必须单独报告) |

## 判定口径(内联,与 todo-writing-standard 技能按质规则同源)

**三层结构**:大目标(3-6 个月)/ 小目标(1 周-1 个月)/ TODO(1-2 天,最长 3 天)。
**判定要点**:
1. TODO 写法是硬要求:不是「要干什么」,而是「什么时间干成满足什么标准的什么事」——只写动作即缺要素,必须带时间节点与标准。
2. 粒度超限即违规:TODO 超过 3 天说明没拆到位。
3. 大小目标对应关系要成立:小目标必须挂在大目标下;至少 1 个大目标有对应小目标(全部没有 = 违规)。
4. TODO 能有 deadline 的必须有;持续项(长期反复、无自然终点)写明「持续项」即可,不能拿它规避 deadline。
5. 每期 TODO 条数 ≤ 5 条。

## 流程

1. 换 token 后读表:认表头、定位最新日期列(当期列)、读人名列。
2. 逐人判定(全员):
   - **未填**(空白)→ 先 `feishu_leave_query` 查该日已通过请假:请假免填 → 跳过;无请假 → 按「按时」违规,私聊提醒「<姓名>,今天(<日期>)的 TODO 还没填」+ 规范要点(同 14:30 提醒口径);
   - **已填** → 按上面判定口径逐项检查,记录每个人的违规项(哪一层、缺什么)。
3. 用 `feishu_message_send` 私聊:已填但不规范的人,只说他具体缺什么(如「你的 TODO 第 3 条没有 deadline」「你的小目标没有挂在大目标下」),不复述规范全文;每条消息只含他本人的问题,不提其他人。

## 硬顺序与红线

- 查假在下结论之前(同 todo-remind 硬顺序);数不准、日期对不上、表结构没读明白 → 归「待人工确认」,不要塞进违规名单凑数。
- 读表/查假失败要明说查询失败,不得顺势判违规。
- 本任务只管「填没填、写得规不规范」;真实性判定归 16:00 的 todo-check,闭环判定归 company-todo-audit,不越界。
- 检查报告是事实判定,不是绩效评价,不加评价性措辞。
- 私聊发送一律用 `feishu_message_send`(定时触发回合没有会话可回,不调用就是没发)。
