# 方案评审结论口径(SOP v2)

结构/硬闸门见 [`proposal-writing-standard`](../proposal-writing-standard/SKILL.md)
(**权威 = 执行跟进与验收 SOP v2.0 四期**, 不是旧 RFC 11 章).
本文只给**建议档位**, 并通过时同步跟进定时.

**刻意为之:** 不得 binding「建议立项」.

**跟进:**
- **可进入深评** → writing-standard **C.同步定时** (`prop-<proposal_id>-*`).
- 其它档位 → **禁止**新建定时.

## When to use

- 检查之后问「能立项吗 / 评审结论 / 动机过不过」.
- 要一页纸建议档 + 依据.

## When not to use

- 要不要写方案 → `proposal-need-remind`.
- 只要改稿/查缺 → 只用 `proposal-writing-standard`(通过时它自己也会同步定时).
- 材料到达对照 → acceptance-poc/doc.

## 加载顺序

```text
要评审
  → 无报告则先按 writing-standard(v2) 检查
  → 本文给四档之一
  → 可进入深评 → C.同步定时; 否则只改稿
  → 声明最终拍板归验收人/评审会
```

## 四个档位(唯一允许词)

| 档位 | 最低条件 |
|---|---|
| **可进入深评** | writing 硬闸门全绿(含四期结构、执行性绝对 DDL) |
| **需补齐后重提** | 动机过; 有可修硬违规(缺期、缺备选「不做」、仅有 T+N 无锚点日等) |
| **叫停·动机不过** | 结论/用户/验收人入口失败 |
| **待人工深评** | 检查不完整或技术深度吃不准 |

禁止「基本可行」「建议立项」.

## 档位规则(硬)

1. 动机不过 → 只能「叫停·动机不过」.
2. 动机过 + 任一硬违规 → 「需补齐后重提」(除非不完整 → 待人工).
3. 全绿 → 「可进入深评」并 **同步定时**.
4. 采集失败 → 「待人工深评」, 不建定时.
5. **旧 11 章壳且未改写成四期** → 不得「可进入深评」(结构违规).

## 报告模板

```text
方案评审建议(SOP v2) — <标题> (proposal_id=<id>)

建议档位: <四档之一>

| 项 | 结论 | 时期/块 | 规则 | 依据 |
|---|---|---|---|---|
| 结构 | … | 预备/实验/实施 | 结构 | … |
| 动机 | … | 结论先行/用户 | 动机 | … |
| 决策 | … | 核心决策点/备选 | 决策 | … |
| 证据 | … | 实验期 | 证据 | … |
| 执行性 | … | 里程碑倒排 | 执行性 | DDL/验收门 |

必须补齐: …
定时: 已同步 prop-<id>-* | 未同步(…)

说明: Agent 建议非立项结论; 最终由 <验收人> 决定。
```

## Boundaries

- 不替验收人最终决策; 报告须有免责声明.
- 定时组规则只认 writing-standard 参数段.
