# 周中对齐会会议 SOP（规则快照）

> 本文件是**规则快照载体**：由 `meeting_pipeline_run` 按 `MeetingJob.analysis_sop_skills`
> 显式注入每次分块与合成分析请求，替代把规则写死在系统提示词里的旧做法，让"按哪一版
> 规则、哪一条判断"可审计。**规则正文（业务条目）待产品/管理口径定稿后填入 v1.0**；
> 定稿前保持既有行为：按下方"分析纪律"执行，SOP 条目判断仅对原文中有明确证据的
> 部分下结论，其余写"待补充证据"。
>
> 修改记录：v0.1-draft（机制上线）——正文占位，规则条目待定稿。

## 使用边界

- 仅由固定会议的调度分析链路（`meeting_pipeline_run`）注入，人工会话不得引用本文件
  冒充已生效的公司 SOP。
- 只判断**原始转写中明确出现**的事实是否违反/符合 SOP；智能纪要仅辅助定位话题，
  不能作为 SOP 判断证据。
- 证据不足时输出"待补充证据"，不得臆测或按默认通过处理。
- 产出的是**候选与观察**：不写正式记录、不触发处罚或绩效，结论供固定收件人人工查看。

## 分析纪律（v0.1 生效部分）

1. **证据层级**：原文 > 纪要辅助；区分事实、发言人陈述、Agent 推断。
2. **SOP 符合性判断**：按"会前准备 / 会中议题与决议 / 会后跟进闭环"三个观察面检查，
   逐条给出 符合 / 部分符合 / 不符合 / 证据不足 四态，并附原文依据（时间+发言人）。
3. **负面观察**：描述可观察行为本身，不贴标签；给出 正确做法 / 立即补救 / 预防措施。
4. **输出归属**：每条判断可回到 会议号 + 日期 + 原文片段，不得出现无出处结论。

## 业务规则条目（待产品定稿后填写）

- [ ] 会前：议题预告、材料齐备、人员到齐的判定标准与例外
- [ ] 会中：议题聚焦、决议项与负责人记录、时间盒的执行口径
- [ ] 会后：跟进项闭环、周中对齐节奏（周一/三/五）的格式与产出要求
- [ ] 例外与免责：临时变更、缺席代理、紧急事项的宽容边界
- [ ] 负面判定示例与反例（定稿时由管理口径评审，避免机械判定）
