# 个人 ToDoList 文档 → 团队 TODO LIST 表格

把**一篇个人 ToDoList docx**里的待办,按 `@人名` 拆开归到各人名下,转成**团队 TODO LIST
电子表格**的单元格格式,写进**调用方指定的列**。

三条硬规则,任何时候都不许自己放宽:

1. **归属按 `@人名` 拆** — 条目行里 @了谁,这条就归谁,写进那个人的行。没 @任何人的条目
   归**文档主人**(文档标题「XX的ToDoList」/「XXToDoList」里的那个 XX)。
2. **目标列由调用方显式给** — 绝不从源文档的日期段自己推列。调用方没说列/单元格就**问**。
3. **目标单元格非空时先报警** — 不许直接盖。把现有内容摘出来给用户看,等明确确认才写。

## 两类文档的形态(结构靠现场探,别写死)

下面的示例取自一次真实运行(源 `wiki/W7vDwWrblii…`「牛志宇ToDoList」→ 目标
`wiki/H6icwLWn1i…`「TODO LIST」),**只是样例,不是硬编码**。换一篇个人 ToDoList、
换一张看板表都要照样能用,所以每次都**先探结构再动手**:表头是哪几列、人名在哪一列、
工作表 `SHEET_ID` 是什么,统统当场读出来,不许沿用上面的示例值。

源和目标**通常不是同一种文件类型**,这是最容易踩的坑:

| | 源(个人 ToDoList) | 目标(团队看板) |
|---|---|---|
| 类型 | 一般是 **docx** | 一般是**电子表格 sheet** |
| 读法 | `feishu_doc_read("docx", obj_token)` | `feishu_sheet_read(obj_token, "SHEET_ID!A1:H30")` |

链接是 `/wiki/` 开头时,后面那串是 **node_token,不能直接当文档 id 用**:
先用 `feishu_api` 打 `GET /open-apis/wiki/v2/spaces/get_node` 换 `obj_token` + `obj_type`,
再按 `obj_type` 决定走 docx 还是 sheet 读法。**先换 token,再读**,顺序错了就是一路 404。
链接本来就是 `/docx/` 或 `/sheets/` 的,那串就是 `obj_token`,不用换。

### 源 docx 的结构

按日期倒序分段,最新的在最前面:

```
牛志宇ToDoList
7-27                     ← 日期段标题
大目标：
  最牛逼的 Agent  -- 2026-12-31
  标准：有用户量,且愿意花钱订阅
子目标：
  子目标 1：推进 demo 在企业内部测试并拿下"种子"用户(8 月底)
ToDo：
  置顶：随时准备配合市场工作
  NL2KE @王浦丞                                    ← @别人 → 归王浦丞
  KE2SQL:拓宽 KE 形式 @牛志宇                       ← @自己 → 归牛志宇
  搭建测试平台(8-9)                                ← 没 @人 → 归文档主人
    急用,先给出半自动测试框架(7-29)                 ← 子层级,跟着父条目走
  date算子层 (7-26)
    Day1:预期:提出方案,方案过审,开始实现            ← Day1/Day2 进度行,跟着父条目
    Day4(7-27):状态:不及预期,PR待人工终审
7-25                     ← 上一段(旧的,默认不搬)
...
```

**默认只取最新那一段日期**(文档最上面那个)。要搬别的日期段,调用方明说。

### 目标 sheet 的结构

典型形态是**列 = 日期,行 = 人**(下表是那次真实运行读到的样子,仅供理解):

| | A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|---|
| 1 | `tag` | `人名` | `mentor` | `7.24` | `7.27` | `7.29` | `7.31` |
| 2 | | @刘律廷 | @郑淳 | …整段文本… | | | |
| 7 | | @牛志宇 | @潘逸轩 | | | | |

**别假定人名一定在 B 列、表头一定在第 1 行**。每次都读一块表头区域
(如 `SHEET_ID!A1:J5`)自己认:哪一行是表头、哪一列的值像人名(mention / 姓名),
就以读到的为准。列数、日期个数、人数都会变。

- 人名列、mentor 列常是**飞书 mention 富文本**(`@某人`),不是纯字符串。
  用 `feishu_sheet_read` 读会自动拍平成 `"@某人"`,**匹配人名时把开头的 `@` 去掉再比**。
- 一个单元格里放**该人当天一整段多行文本**(大目标 / 子目标 / Todo + 标准),不是一行一条。
- 表头日期可能是 `7.24`(点分),源文档里可能是 `7-27`(横线分)。**格式不同,不要拿来自动对齐**
  —— 列由调用方给,这条只是提醒你别自作聪明。

## 干活步骤

### 1. 换 token,认清类型,找到工作表

`/wiki/` 链接先换 token(`/docx/`、`/sheets/` 链接跳过这步):

```
feishu_api(method="GET", uri="/open-apis/wiki/v2/spaces/get_node",
           query_json='{"token": "<源 node_token>"}', user_key=…)    → node.obj_token=…, node.obj_type=docx
feishu_api(method="GET", uri="/open-apis/wiki/v2/spaces/get_node",
           query_json='{"token": "<目标 node_token>"}', user_key=…)  → node.obj_token=…, node.obj_type=sheet
```

结果在 `data.node` 里。**返回成功但 `node` 是空的**说明机器人不是这个知识库的成员 ——
不是节点不存在,带 `user_key` 加 `prefer="user"` 再问一次。

`obj_type` 与预期不符(比如目标是 docx 不是 sheet)就**停下来说清楚**,别硬写。

再拿目标表的 `SHEET_ID` —— **它不在 URL 里,必须查**:

```
feishu_api(method="GET", uri="/open-apis/sheets/v3/spreadsheets/:spreadsheet_token/sheets/query",
           paths_json='{"spreadsheet_token": "<目标 obj_token>"}', user_key=…)
  → data.sheets:[{sheet_id, title, index, grid_properties:{row_count, column_count}}]
```

多个工作表时按 title 选(或问调用方),别默认第一个。

### 2. 读源文档,切出最新日期段

`feishu_doc_read("docx", <源 obj_token>)`。拿到纯文本后:

- 第一行通常是标题(如「XXToDoList」),从中取**文档主人**的名字。
- 找最上面那个日期段标题(`7-27` / `7.27` / `07-27` 都可能),切到下一个日期标题为止。
- 段内按缩进还原层级:`ToDo：` 下的一级条目 + 它的子条目 / `Day1:` 进度行。
- `大目标：` / `子目标：` 段落是**共有背景**,不属于任何单个 @人。

标题里认不出主人,或者压根没有日期分段,就**如实说结构和预期不符**并把读到的结构讲清楚,
让调用方确认怎么切,别猜着搬。

### 3. 按 `@人名` 拆归属

对最新段里 `ToDo：` 下的**每个一级条目**:

- 条目文本(含其子条目/Day 行)里出现 `@某人` → 这条归**某人**。
  一条里 @了多个人 → 这条**分别进每个被 @的人**的内容里,原文保留。
- 一个都没 @ → 归**文档主人**(标题里的那个人)。
- `置顶：…` 这类没 @人的,同样归文档主人。

拆完得到 `{人名: [条目...]}`。**@到的人可能不在表里**(表里就那几十行固定人员)——
不在就**如实报告"@某人 有 3 条但表里没这个人,已跳过"**,不许自己加行。

**`@` 后面的名字要按表里的人名对齐,别把后面跟着的字吃进来**:原文有
`NL2KE收口收窄,@王浦丞的ToDo` 这种写法,贪心截取会得到「王浦丞的」这个不存在的人。
做法是拿第 4 步表里的人名列表去**反向匹配**(看 `@` 后面是否以某个已知人名开头),
而不是硬套「@ + 2~4 个汉字」。**所以第 4 步(读人名列)可以先做**,拿到人名表再回来拆归属。

### 4. 定位每个人的行

`feishu_sheet_read(<目标 obj_token>, "<SHEET_ID>!A1:J40")` 一次读够表头 + 人名列
(行数不够就把范围调大,`sheets/query` 给的 `row_count` 是表格上限而不是有数据的行数)。先认出:

- **表头在第几行** — 那行里出现日期样式(`7.24` / `7-24` / `7月24日`)的就是它。
- **人名在第几列** — 该列大部分单元格拍平后形如 `@某人` / 两三个字的姓名。

再把人名列去掉 `@` 与前后空白,和第 3 步的人名**精确匹配**得到行号。

匹配不上就报告,不要模糊匹配到别人身上。

### 5. 组装单元格文本

每个人的单元格是**一段多行文本**。**照目标表里已有的非空单元格的样子来** —— 先挑一个
已填好的格看它的写法(小标题怎么写、编号用 `1.` 还是 `-`、缩进几个空格),再照着排:

```
大目标：
1. <大目标>(<期限>)
   标准：<标准>

子目标：
1. <子目标>(<期限>)
   标准：<标准>

todo：
1. <这个人被 @ 的条目>(<期限>)
   a. <子条目>(<期限>)
   Day4(7-27)：状态：… 预期：…
```

- 大目标/子目标是共有背景,**每个人的单元格都带上**(它们描述的是团队方向)。
- `todo：` 下**只放这个人自己的条目**,原文的期限、`标准：`、`Day1/Day2` 进度行都保留。
- 保持纯文本 + 换行 + 空格缩进。写入时这一格就是一个字符串,**换行用 `\n`**。

### 6. 查目标单元格是否已占

写之前必查。列由调用方给(如「E 列」/「7.27 那列」→ 先在第 4 步认出的表头里
找到 `7.27` 是哪一列),行是第 4 步得到的:

```
feishu_sheet_read(<obj_token>, "<SHEET_ID>!<列><行>:<列><行>")
```

- **空** → 直接进第 7 步写。
- **非空** → **停**。把现有内容(截前 200 字够了)连同"这格已有内容,确认覆盖吗?
  也可以改写到别的列"一起给用户,**等明确确认**才写。多个人都非空,一次性列全,别一个个问。

### 7. 写入

```
feishu_sheet_write(<obj_token>, "<SHEET_ID>!E7:E7", '[["大目标：\n1. …"]]')
```

- 一格一次写,`values_json` 是 `[[ "整段文本" ]]`。
- 多个人可以一次写一列的连续区间(如 `E2:E10`),但**中间不该动的行要用原值填回去**
  —— 拿不准就**一格一格写**,更安全。
- 单元格文本以 `=` 开头会被当公式。源文本理论上不会,真遇到就在前面加个空格。

写完复述:谁写进了哪个单元格、哪些人跳过了、哪些格是覆盖的。

## 被问「完成情况」时:本 skill 不判定

本 skill 只**搬运**,不判某条 todo 做完没有。用户接着问「谁做完了」「这条闭环了没」
「XX 这周完成情况怎么样」时,**先加载 [`todo-completion-standard`]**,按那份总纲的四档
(`已完成` / `推断已完成／待确认` / `进行中` / `未闭环`)和 E1-E3 取证链判。

尤其别在这里就地下结论:你手上只有源文档和看板,那是最弱的 **E3(本人自填)**。
「到期后从后续日期段里消失」在总纲里统一算 `推断已完成／待确认`,不是「已完成」也不是
「未闭环」,而且**对同一批人里的每个人都一样**。

## 被问「写得规范吗」或要帮人组织内容时:换 skill

本 skill 只搬运**一篇现成的个人 ToDoList 文档**,既不判填报是否合规,也不替成员组织内容。
换用 [`todo-writing-standard`] 的场景:

- 「帮我把这几件事写成 todo list 填到表里」—— 源是**零散输入**(口述、几条消息、散落的任务),
  不是一篇成形的 ToDoList 文档,需要按规范识别层级、补全要素、缺信息先问再写。
- 「检查 todo 填得规范吗」「谁不合规」「格式对不对」—— 那份技能持有内容格式规范与执行纪律。

分界是**源的形态**:成形文档按 `@人名` 拆 → 本 skill;零散输入要组织成规范三层 → 那边。
本 skill 不校验搬进去的内容是否合规,只保证搬得准。

## 权限

两篇文档都要该 app 是协作者,否则 tenant token 读写都 403。
拿不到就走 `feishu_auth_start()` 让本人授权,再带 `user_key=<sender_open_id>` 以本人身份读写。

**读的两步(`feishu_api` 打 get_node / sheets query)和 `feishu_sheet_read` 也都收
`user_key`**:它们是 tenant 优先,只在机器人被拒时才回落到该用户身份,所以**表格可能归个人时
就一路把 `user_key` 带上**,别等 403 了才补。写操作默认就以用户身份走(`prefer="user"`),
`user_key` 空则回落 tenant。整条链路(get_node → sheets query → read → write)要用**同一个**
`user_key`。

## 别做的事

- 别把本文的示例值(`46a582`、E 列、第 7 行、那两个 wiki token)当常量用 —— 每次现场探。
- 别自己推目标列(表头日期和源文档日期格式往往不一样,推错就写串行)。
- 别静默覆盖非空单元格。
- 别给表里没有的人新增行。
- 别把 `大目标/子目标` 当成某个人的 todo 拆走。
- 别一次搬所有历史日期段,除非调用方明说。
