# 正负面分析规则（自动化上下文快照）

> 本快照从 `positive-negative-list/SKILL.md` 抽取**规则本体**，供自动化上下文
> （固定会议定时分析等）注入，避免把带"仅人工私聊触发/不得用于定时任务"边界的
> 整篇 SKILL.md 塞进调度管道造成自相矛盾。
>
> **同步义务**：修改 `SKILL.md` 的规则内容时须同步本文件；规则以
> `positive_negative_rules` 动态查询为准，本快照只承载会议分析可用的判断纪律与
> 参考轴，不替代规则库查询（自动化上下文无该查询工具）。

## 应用边界

- 分析对象是**会议原文转写中明确出现的行为事实**；不得把原文外的猜测写成事实。
- 产出是**候选与观察**：不写正式总表、不计分、不排名、不进入绩效、不自动认定红线、
  不自动通知 HR/法务；候选须经人工确认后才进入既有卡片闭环。
- 引用规则/分类时以可观察行为为准，不先预设结论再找支持证据。

## 判断纪律

1. **行为性质**：`positive`、`negative`、`neutral`、`insufficient_evidence`；信息
   不足只写"待补充证据/初步对应"，不得使用"已确认/定案/命中"。
2. **事实分层**：区分 可观察事实、当事人/他人陈述、Agent 推断、规则引用；个人陈述
   必须标明"当事人陈述/他人陈述"，不得写成已核实事实。
3. **事件边界**：候选按事件而不是按单条消息/单句话划分；同一事件跨段补充的事实要
   累计，不重述；不同事件不合并。
4. **证据来源**：每条结论可回到 时间戳+发言人+原文片段；跨段无法互相印证的内容
   明确标记待补充证据。
5. **红线谨慎**：只有可观察事实本身满足疑似违法、重大安全风险或严重制度违规且有
   相应原始证据时，才使用红线候选措辞；不能仅因涉及法务、制度、对外发布或使用合规
   词而升格。普通审批或复核缺失本身不是红线触发事实。
6. **负面候选三元组**（缺一不可）：
   - `correct_behavior`：符合价值观/制度的正确做法；
   - `immediate_remedy`：这次事件现在如何补救；
   - `prevention`：以后如何防止再犯。

- 结果优先：出现上表所列负向直接用户结果时，主条目即"用户第一"，核验/反馈/流程
  闭环只作关联条目；仅有潜在影响、投诉或对外发布而无明确验收失败等结果时不自动升格。
- 分类按"价值观轴 | 行为条目"两段表达；只引用规则库返回的稳定 ID，不编造规则 ID。
- 疑似重复/跨源部分相似须标出，由人工判断是否独立行为，不自动合并。
