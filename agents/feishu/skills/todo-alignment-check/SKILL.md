# TODO 对齐与价值判定总纲（静态三层）

判断「目标与价值写得对不对齐」只有这一套口径。SOP：大目标要与组织上一级大目标对齐、成果来自外部；大目标/小目标/子目标都要以 TPMF 闭环为标准、以用户为中心，说清为**用户**带来什么价值而不是要做什么事；大目标突出**友商比较**与**外部成果**；个人 TODO 与**小组** TODO 对齐；申请上级验收、验收过了才算完成。

填得规不规范 → [`todo-writing-standard`]；做得真不真 → [`todo-truthfulness-check`]；本文管的是**对不对齐、有没有价值与成果**。

存在的理由：

- 对齐和价值是「关系」问题，不是「有没有写」的问题：三层结构齐全、deadline 都写了，目标照样可以不对齐上级、不说用户价值、不写外部成果——这正是静态三层要抓的。
- 判对齐需要事实：上级的当期大目标在哪、小组的目标在哪、价值/成果有没有可核对的量化表述。**拿不到上级目标就判不了对齐**——所以可对齐性（A1）先行，缺上级信息不判「未对齐」。
- 判错的三个方向都要防：把「拿不到上级信息」判成「未对齐」（冤枉人）、把「没写价值/成果」判成「失实」（那是静态二层的领域，不是对齐）、只拿本人自填对本人自填（双标）。

## When to use

- 「他的目标对齐上级了吗」「个人和小组对齐吗」「这条写清用户价值了吗」「外部成果 / 友商对比在哪」「验收过了没有」。
- 读一篇团队看板 / 大目标·小目标后要给出「对齐 / 价值 / 成果」结论。
- 一次问询涉及多人、要给可比结论时（**最必须**加载的场景）。

## When not to use

- 判**真不真**（声明与事实是否一致）→ [`todo-truthfulness-check`]。
- 判**活走完整圈没有**（台账闭环五要素、逾期回流）→ [`company-todo-audit`]。
- 判**填得规不规范**（三层结构 / 按时按质按量）→ [`todo-writing-standard`]。
- 判**做完没**（完成度四档）→ [`todo-completion-standard`]。
- 搬运个人 ToDoList → [`feishu-todo-board-sync`]。

## 分界（同一张表，互不覆盖）

- **不合规 ≠ 未对齐**：格式差是水平问题，不是「没对齐上级」。
- **失实 ≠ 未对齐**：写「外部成果 1 亿」但其实是假的，那是真伪问题（静态二层），不是「没写成果」。
- **闭环 ≠ 对齐**：一条走完台账五要素的 todo，目标照样可能不对齐上级、不写用户价值。

## 声明-价值对照（claim–value reconciliation）

一条大目标/小目标的价值声明含五个要素，每个都要能找到事实，找不到就是「无法判定」的候选：

| 声明要素 | 事实源 | 证据级 |
|---|---|---|
| 与上级大目标对齐 | wiki 组织树里上级的**当期**大目标（`company-todo-sync` 快照维护） | E2/E3 |
| 与小组目标对齐 | 小组目标页 / 当期看板里小组条目 | E2/E3 |
| 以用户为中心的价值 | 大/小目标正文里「为谁、带来什么价值」的量化表述 | E3 |
| 外部成果 / 友商对比 | 大目标正文里的量化成果（用户/金额）与友商比较 | E3 |
| 上级验收 | 验收状态机：已申请验收 → 验收中 → 通过 / 驳回 | E2 |

E1-E3 沿用 [`todo-completion-standard`]：E1 = 任务系统里该执行人自己的 `completed_at`；E2 = 第三方确认（验收人/群/文档评论）；E3 = 本人自填（看板 / wiki 快照 / 自评）。本文用它判「对齐与价值」的事实，不判完成度、不判真伪。

## 四个档位（唯一允许的结论词）

| 档位 | 什么时候用 | 最低证据 |
|---|---|---|
| **对齐** | 上级对齐 + 用户价值 + 成果/友商 + 验收 均到位 | E2 或 E3 |
| **存疑／待跟进** | 有部分要素，但证据不足、含糊，或验收未通过却写完成 | E3 或部分证据 |
| **未对齐（价值/成果缺失）** | 明确缺：不对齐上级 / 不写用户价值 / 大目标无外部成果或友商对比 | E3 的缺失证据 |
| **无法判定** | 缺上级目标可对、缺小组信息、读不到当期填报 | 任意（提示补数据，不判违规） |

**只准用这四个词。** 禁止「基本对齐」「应该没问题」这类自造档位。

判不准 → `存疑／待跟进` 并写清缺什么，**不要**私自往两头靠。

**「未对齐」是提示级结论**：提醒本人/mentor 补写，不判违规、更不判失实——价值/成果缺失可能是没写清楚，不是写了假的（真假归 [`todo-truthfulness-check`]）。

## 对齐维度（A1-A6，逐条对应 SOP）

| 维度 | 检查什么 | 判定要点 |
|---|---|---|
| **A1 可对齐性** | 每条大目标是否**有上级当期大目标可对**（组织树已建、上级已填报） | 缺上级信息 → `无法判定`（先催补组织树/上级填报，不判未对齐）|
| **A2 上级对齐** | 本人大目标 ↔ 上级当期大目标（语义对齐 + 置信度 + 依据） | 语义不对齐 → `未对齐` 嫌疑；拿不准 → `存疑／待跟进` |
| **A3 小组对齐** | 个人 TODO ↔ 小组 TODO（主题/目标一致性） | 不对齐 → 提示并给依据 |
| **A4 用户价值** | 以用户为中心，说清「为谁、带来什么价值」而非只写动作 | 只写动作不写价值 → `未对齐`（价值缺失）|
| **A5 外部成果/友商对比** | 大目标必含量化外部成果（用户/金额）与友商比较 | 缺失 → `未对齐`（成果缺失）；大目标选填变必含；外部成果词表与证据口径读 `config/todo-sop.yaml` 的 `external_outcome` 段 |
| **A6 验收** | 申请上级验收、验收通过才算完成（复用 #784 验收状态机） | 未申请/验收未通过却写完成 → `存疑／待跟进` |

SOP 原文（引用依据时用）：大目标与组织上一级大目标对齐，成果来自外部；大目标、小目标、子目标都需要以 TPMF 闭环为标准、以用户为中心、说清为用户带来什么价值，而不是要做什么事；都需要申请上级验收、验收过了才算完成；TPMF 小组长的目标闭环中还要重点突出和友商的比较；个人 TODO 要与小组 TODO 对齐。

## 数据源

- **上级当期大目标**：LLM wiki 组织树（`feishu_sync_org_tree` 维护的「组织关系」区块给出上级是谁；`company-todo-sync` 维护的快照页给出上级当期大目标）。上级没填当期 → A1 `无法判定`，不判未对齐。
- **小组目标**：小组目标页 / 当期看板里小组条目。
- **当期填报 + 快照**：看板当期列（`feishu_sheet_read`）+ wiki 快照（`wiki_read`）。

读组织树 / 快照失败（无权限、缺页）→ 照实报 `unavailable`，按防误判纪律处理，不顺势判。

## 防误判纪律（与完成度/实事求是总纲同源，不许放宽）

1. **取证对称性**：一次问询涉及多人时，对每个人跑同一条链；某人某级取不到 → 标 `unavailable`，全体降到同一深度重判。
2. **先验印象隔离**：本人自评、历史表现、他人评价不作证据，只进「背景」区并标来源。
3. **查询失败明说**：查不到 ≠ 无记录；读表/读 wiki 失败必须写「查询失败」。
4. **缺上级信息 = 无法判定 ≠ 未对齐**：组织树没建、上级没填当期，都不能判「未对齐上级」。
5. **价值/成果缺失 ≠ 失实**：缺价值/成果归本文（提示补写），真假归 `todo-truthfulness-check`。

## 报告格式

```
| 条目 | 档位 | 证据等级 | 依据 |
|---|---|---|---|
| 大目标：记忆系统 | 对齐 | E3 | 对齐上级「NLP 平台」当期大目标；写清为记忆团队带来 20% 召回提升 |
| 大目标：NL2KE | 未对齐（价值/成果缺失） | E3 | 只写「做完 NL2KE」，无用户价值、无外部成果、无友商对比 |
| 小目标：date 算子 | 存疑／待跟进 | E3 | 写「提升性能」但无量化；验收状态未查到 |
| 大目标：搭建测试平台 | 无法判定 | E3 | 上级未填当期大目标，无上级目标可对 |
```

多人按人分组，每组开头写**实际达到的取证深度**；收尾列「要定论还缺什么」（哪条需要谁确认、哪条要补什么数据）。

## Boundaries

- 不编造上级目标、小组目标、成果数字；查不到就是 `unavailable`。
- 「未对齐」是提示级结论（提醒补写），不是违规、不是失实、不是绩效评价。
- 对齐/价值是事实判定，不加评价性措辞，不向无关成员披露。
- 判定只回答「对不对齐、有没有价值与成果」。要不要处理由用户拍板。

## 判定口径

档位词、A1-A6 维度名、大目标必含的外部成果 / 友商对比，权威在 `config/todo-sop.yaml` 的 `alignment` 与 `schema` 段（用户可编辑，换公司只改该文件）；本文保留 A1-A6 的判定纪律与「从哪验证」，与其它判定 skill 同一模式。
