# guoshu-weekly-frontend

国数周报 Agent 的专属对话前端(方案 6.1),React + TypeScript + Vite。

四视图全部就绪:对话(主视图)、历史(会话列表 + 按轮次问答 + 导出)、报告(周报总结生成 + 下载列表)、登录(试用账号)。

需求功能清单覆盖(见《需求说明》P0-P2):

- **P0** 多轮对话(上下文记忆)/ 个性化选项(身份/输出偏好)/ 简单可视化
- **P1** 周报总结 Word 下载 / 复杂可视化(饼图/条形/折线三态切换 + PNG 下载)/ 对话历史 Excel/PDF 导出
- **P2** 一场对话多轮上传材料分析:Excel/PDF/Word/文本,点击 📎、拖拽进对话卡、Ctrl+V 粘贴三种上传方式,跨轮次引用已传材料

对话体验(方案 6.2):SSE 首 token 即时渲染、工具调用进程行实时呈现(回答中「… 工具名」→「✓ 工具名」)、答案依据折叠核查、可排序表格答案(数值列按数值、文本列按拼音,表头 ⇅/▲/▼)。

## 启动

```bash
npm install
npm run dev      # http://localhost:5173,/api 经 vite 代理转发到 BFF(127.0.0.1:8780)
```

依赖:BFF 已启动(见 ../guoshu-weekly-bff/README.md「全链路启动」),BFF 背后是 gateway、guoshu agent 包与取数 MCP 服务。

## 联调链路

```
浏览器(5173)→ vite 代理(/api)→ BFF(8780)→ gateway(8766)→ agent 包 → MCP 取数服务(demo 为 mock 18901)
```

前端只认识 `/api`,永远不知道 Gateway 地址与密钥(方案 6.2/6.3)。

## 边界与约定

- **登录**:试用账号(demo/demo),BFF 签发 httponly 会话 cookie;注册与邀请码在公网试用阶段落地。
- **流式渲染**:fetch + ReadableStream 逐行消费 SSE(EventSource 不支持 POST),收到一行渲染一行——首 token 可见依赖这里不做缓冲。
- **个性化面板**:身份(领导/员工)与输出偏好(结论/过程优先)为 demo 阶段页内切换,由 BFF 注入为「回答组织指令」;生产阶段身份来源换成登录角色(方案 6.2:身份取自可信标识,前端切换不得成为越权入口)。
- **会话**:sessionId 存 localStorage;会话注册表(上限 60 条)支撑对话页/历史页切换;401(会话失效)自动退回登录页。
- **图表**:前端原生 SVG 渲染 + 导出 PNG(方案 6.1 原定后端出 PNG,实现改为前端渲染+导出,屏上与导出同一份数据源);图表数据取模型最后呈现的表(最相关维度)。
- **视觉基准**:《周报 POC 离线交付包》03 核心对话版(绿色主色、卡片对话、结论先行)。
- **演示数据**:页面常驻「演示数据,非集团真实周报」明示(方案 10.2)。
